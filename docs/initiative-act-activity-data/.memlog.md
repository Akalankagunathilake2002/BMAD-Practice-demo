- (decision) 2026-11-15, B: stories whose check needs a later module move to that module: demo-data seeding to M2, factor version 1 seeding to M3, headline figures to M3, the period-edit guard to M2. M0 keeps the seed command and demo users.
- (requirement by sofia) R1 (ACT.FR-1; parent R17, R23): A user adds an activity in a dialog with type, quantity, date and optional description, the unit following the type; the save calls M3's calculation in the same step, the new row shows its emissions and factor, and when the activity falls outside the selected period the confirmation offers to switch to its period.
- (requirement by sofia) R2 (ACT.FR-2; parent R18): The server refuses, each with its error at its field, a quantity of 0 or less, over 1,000,000,000 or with more than 3 decimals, a date after today or outside every period, a description over 500 characters, a unit not matching the type, and a type with no active factor.
- (requirement by sofia) R3 (ACT.FR-3; parent R19): Each saved activity is linked to the one period of its organization that contains its date; the user never chooses the period.
- (requirement by sofia) R4 (ACT.FR-4; parent R20): The Activities page opens on the selected period with an "All periods" option, filters by type, period and date range (a date range overriding the period), sorts by date (newest first by default), type, quantity or emissions, pages 25 rows by default and up to 100 with the total shown, and keeps filters and sort in its address.
- (requirement by sofia) R5 (ACT.FR-5; parent R20, R25, R31): Each row shows date, type, quantity with unit, description, emissions in kg CO2e to 2 decimals and the factor used (value, unit, version); the page shows the disclaimer, and each row's calculation history opens from it.
- (requirement by sofia) R6 (ACT.FR-6; parent R21): Editing changes type, quantity, date or description under R2's rules; a type change switches the unit, keeps the number and says the unit changed; a new date in another period moves the activity there; every saved edit is recalculated, and the last save wins.
- (requirement by sofia) R7 (ACT.FR-7; parent R16): The Activities page opens with a period and a date range from its address applied; M1's refused period edit links here.
- (requirement by sofia) R8 (ACT.FR-8, Should; parent R22): Delete asks for confirmation naming the activity's date, type and quantity and saying there is no undo, then removes the activity and its calculation history from every total.
- (requirement by sofia) R9 (ACT.FR-9, Could; parent R33): Each row shows its activity type's informational scope label from the reference data.
- (requirement by sofia) R10 (ORG.FR-8; parent R16): A period edit that would leave any of its activities outside its new dates is refused, with the count and a link to them (R7).
- (requirement by sofia) R11 (PLT.FR-11; parent R4): With demo seeding on, the seed command creates 2 fictional organizations with calendar-year periods and fixed-date activities from May 2025 to October 2026, all passing the app's own validation, and leaves existing organizations untouched when run again.
- (constraint by sofia) An activity's period always follows its date, and no activity is ever outside a period (A-04).
- (constraint by sofia) One unit per activity type, with no conversion (A-06, Q-05).
- (constraint by sofia) The server is the authority on validation; the form only gives early feedback (architecture §12.3, NFR-06).
- (constraint by sofia) Demo data uses fixed dates and quantities so its totals are the NFR-01 golden values; moving the date window means updating the seed and the golden values together (PLT.FR-11, moved from M0 by Decision B).
