## 0. Document purpose

This PRD details what M3 must do so that UX (CP4) and epics and stories (CP5) can be written from it. It does not repeat the master PRD. Where a rule already exists there, this document cites its ID (for example FR-EMI-01, NFR-02, G2, J4, Q-18, A-09) and adds only what the master leaves open.

New functional requirements are numbered **EMI.FR-1** onward. Each carries a tag:

- **MVP**: refines a Must requirement in the master PRD, so it is part of the MVP (master §9).
- **Should** or **Could**: refines a master requirement with that priority.

Rules inferred where the source documents are silent are marked `[ASSUMPTION]` and indexed in §9. All of them were accepted at the draft review on 2026-11-14. The tags stay so that story refinement can trace them.

All master non-functional requirements (NFR-01 to NFR-11) apply to M3 unchanged. NFR-01 (exact arithmetic), NFR-02 (aggregate speed) and NFR-08 (test coverage of the calculation code) matter most here.

## 1. Vision

M3 is the part of CarbonTrack that turns activity data into kg CO2e. It keeps every number explainable after the fact, which is goal G2 and business requirement BR-03. Every figure the product shows can be traced to one emission calculation, one factor version and one quantity. Changing a factor never silently rewrites the past.

M3 owns the numbers. M2 (activities), M4 (dashboard) and M5 (reports) display them. M3 also owns the one screen where factors are managed: the Emission Factors page.

## 2. Users and journeys

The personas are defined in [project brief §3](../../initiative-carbontrack/project-brief/project-brief.md#3-users-and-stakeholders). Two of them use M3 directly:

- **Sustainability Manager.** Relies on every emission figure being correct and explainable. Runs a recalculation after a factor changes.
- **Platform Administrator.** Adds new factor versions. Roles are labels only (A-01, FR-AUTH-04), so in practice any signed-in user can do this.

M3 realizes two master journeys and adds the detail below:

- **J2, record monthly activity.** Each save creates a current calculation (EMI.FR-1) and shows its factor (EMI.FR-3).
- **J4, update a factor.** The administrator adds a version (EMI.FR-7) on the Emission Factors page (EMI.FR-8). The manager then sees how many calculations are out of date and recalculates them (EMI.FR-9).

## 3. Glossary

*Activity*, *emission factor*, *emission calculation*, *reporting period* and *GHG scope* are defined in [project brief §5](../../initiative-carbontrack/project-brief/project-brief.md#5-domain-concepts). This PRD adds:

- **Factor version.** One immutable value of an emission factor for one activity type. Versions are numbered 1, 2, 3 and so on for each type.
- **Active factor.** The single factor version for an activity type that new emission calculations use. Each type has exactly one active factor at all times.
- **Current calculation.** The one emission calculation for an activity that totals and breakdowns use.
- **Calculation history.** All of an activity's emission calculations: the current one plus every earlier one.
- **Out-of-date calculation.** A current calculation whose factor version is no longer the active factor.
- **Recalculation.** The explicit action that replaces an organization's out-of-date calculations (FR-EMI-10).
- **Source label.** The text that says where a factor version's value came from. It always contains the demonstration disclaimer.
- **Demonstration disclaimer.** The notice required by FR-EMI-09 and Q-10.

## 4. Features

### 4.1 Calculating on every save

Each time an activity is created or edited, M3 creates a new current calculation with the active factor. The earlier calculation becomes history. Realizes J2. Refines FR-EMI-01, FR-EMI-02 and FR-ACT-05.

#### EMI.FR-1 · MVP: Calculate on every save

Each create and each successful edit of an activity produces a new current calculation using the active factor at that moment.

**Consequences (testable):**
- Every edit recalculates, including an edit that changes only the description. So editing an activity after a new factor version was added moves it onto the new factor. Its earlier calculation stays in the calculation history.
- An activity save and its calculation succeed or fail together. An activity never exists without a current calculation.
- The emission calculation follows the master's arithmetic and rounding rules (master §6, NFR-01).
- `[ASSUMPTION]` If an activity type has no active factor, the save is rejected and nothing is stored. The error uses the standard error envelope (NFR-05) and names the activity type that has no active factor.

#### EMI.FR-2 · MVP: Keep the calculation history

Each activity has exactly one current calculation. Every earlier one is kept.

**Consequences (testable):**
- After N saves of an activity, it has N emission calculations, exactly one of them current.
- Emission calculations are never edited. They are only added, and they are removed only when their activity is deleted (FR-ACT-06).
- Totals and breakdowns (§4.3) use current calculations only.
- An activity's calculation history, oldest first, is available through the activity's detail. `[ASSUMPTION]` Where the history appears on screen is decided in UX (CP4) for the Activities page (M2).

### 4.2 Explaining every emission calculation

Refines FR-EMI-03 and FR-EMI-09.

#### EMI.FR-3 · MVP: Return the factor version with every emission calculation

Every API response that includes an emission calculation also includes the factor version it used: value, unit, version number and source label.

**Consequences (testable):**
- An activity in a list or detail response carries its current calculation and that calculation's factor version.
- Each entry in the calculation history carries the factor version used for that entry, not the active factor.
- How M2, M4 and M5 display this belongs to their own PRDs.

#### EMI.FR-4 · MVP: Keep the demonstration disclaimer attached

The demonstration disclaimer can never be separated from a factor.

**Consequences (testable):**
- Every source label, whether shown or returned by the API, contains the demonstration disclaimer, whatever text the person typed when adding the version (EMI.FR-7).
- The Emission Factors page shows the disclaimer (EMI.FR-8).
- The CSV column that carries the disclaimer (Q-10) is built by M5. M3 guarantees that the source label it supplies already contains the disclaimer.

### 4.3 Totals and breakdowns

M3 calculates the aggregates. M4 and M5 only display them. Refines FR-EMI-04, FR-EMI-05 and FR-EMI-06.

#### EMI.FR-5 · MVP: Total and share by activity type

For one organization, M3 returns the total emissions and each activity type's emissions and share of that total, either for one reporting period or overall.

**Consequences (testable):**
- Only current calculations are counted.
- `[ASSUMPTION]` When no reporting period is chosen, "overall" means all of the organization's current calculations.
- `[ASSUMPTION]` All three activity types are always returned. A type with no data shows 0 kg CO2e and a 0% share.
- `[ASSUMPTION]` When the total is 0, every share is 0% and no error is raised.
- Shares are calculated from exact values. Rounding them for display is the job of the screen showing them.

#### EMI.FR-6 · MVP: Monthly totals

For one organization and reporting period, M3 returns emissions per calendar month of activity date (A-05), in total and by activity type.

**Consequences (testable):**
- A reporting period must be chosen. Its only users, the dashboard trend (FR-DSH-02) and the report summary (FR-RPT-01), always work within one period.
- Only months with at least one activity are returned. Months with no activity are left out, and M4 decides how to show the gaps.
- `[ASSUMPTION]` In a month that is returned, an activity type with no activity shows 0.
- `[ASSUMPTION]` Months are returned oldest first.
- These responses meet NFR-02.

### 4.4 Emission factors

Realizes J4. Refines FR-EMI-07 and FR-EMI-08, and settles Q-18 as option (a): a page with version history and an add-version form.

#### EMI.FR-7 · MVP: Add a factor version

A signed-in user adds a new factor version for one activity type. It becomes the active factor immediately.

**Consequences (testable):**
- Input: the activity type, the value, and optional source text. The unit is fixed by the type (master §6).
- The value must be from 0 to 999,999.999999, with at most 6 decimal places. A value outside that range, or one with too many decimals, is rejected with a field-level error.
- `[ASSUMPTION]` The source text is up to 100 characters. The demonstration disclaimer is always added to it (EMI.FR-4). If it is left blank, the source label is the standard demonstration label.
- The new version gets the next number for its type. The previous version becomes inactive and stays in the history.
- Existing factor versions can't be edited or deleted.
- Factors are shared by all organizations. From that moment, every new emission calculation for that type, in any organization, uses the new version. Existing calculations don't change until they are recalculated (EMI.FR-9) or their activity is edited (EMI.FR-1).
- `[ASSUMPTION]` If two people add a version for the same type at the same moment, one succeeds and the other gets a conflict error asking them to retry. A type never has two active factors.
- Version 1 of each factor is loaded by the seed command (FR-PLT-04).

#### EMI.FR-8 · Should: Emission Factors page

The Emission Factors page, reached from the sidebar (FR-PLT-01), shows the factors and lets the user add a version.

**Consequences (testable):**
- For each activity type, it shows the active factor: value, unit, version number, source label, and the scope label if EMI.FR-10 is built.
- For each activity type, it shows the version history newest first, with the date each version was added.
- It contains the add-version form, with the rules and errors from EMI.FR-7.
- It shows the demonstration disclaimer.
- It has loading, empty and error states, like every data view (G3).

### 4.5 Recalculation

Refines FR-EMI-10 and keeps the A-09 / Q-06 rule that a factor change alone never alters stored results.

#### EMI.FR-9 · Should: Recalculate an organization

The user sees how many of the organization's calculations are out of date, confirms, and those calculations are replaced with ones using the active factors.

**Consequences (testable):**
- Before confirming, the user sees the number of out-of-date calculations.
- If the number is 0, the user sees "All results are up to date". Nothing is asked and nothing changes.
- On confirmation, each out-of-date calculation becomes history, and a new current calculation is created with the active factor.
- Activities whose current calculation already uses the active factor get no new emission calculation.
- Afterwards, the user sees how many calculations were updated.
- `[ASSUMPTION]` Recalculation is all-or-nothing. If any part fails, nothing changes and the user can retry.
- `[ASSUMPTION]` It applies to the organization selected in the top bar. UX (CP4) decides where the action appears.

### 4.6 Scope labels

#### EMI.FR-10 · Could: Show the GHG scope label

Each activity type carries its informational GHG scope label (FR-EMI-11, using the mapping in master §6).

**Consequences (testable):**
- The label comes from the reference data (FR-PLT-06), so every screen shows the same label.
- The Emission Factors page shows each type's label.
- The label is marked as informational, consistent with the master's non-goal of compliance with any reporting framework.

## 5. Non-goals

The master PRD's non-goals (§2) and out-of-scope list (§10) apply. In addition, M3 does **not**:

- recalculate automatically when a factor changes (A-09, Q-06);
- support factors per organization, region or year (A-08, Q-07);
- convert between units (Q-05);
- edit or delete existing factor versions;
- display the dashboard (M4, DSH) or build reports and CSV exports (M5, RPT). M3 supplies their numbers only.

## 6. MVP scope

**MVP:** EMI.FR-1 to EMI.FR-7.
**Should:** EMI.FR-8 (Emission Factors page) and EMI.FR-9 (recalculation).
**Could:** EMI.FR-10 (scope labels).

Without EMI.FR-8, factor versions can still be added through the API and Swagger UI (FR-PLT-02).

## 7. What M3 provides to other modules

| Module | Receives from M3 | Note |
|---|---|---|
| M2 Activities | A current calculation on every save (EMI.FR-1). The factor used and the calculation history (EMI.FR-2, EMI.FR-3) | The activity and its calculation are saved in one transaction |
| M4 Dashboard | Totals and shares (EMI.FR-5) and monthly totals (EMI.FR-6) | Months with no data are left out. M4 decides how to show the gaps |
| M5 Reports | The same aggregates, plus the factor and source label for each line item (EMI.FR-3, EMI.FR-4) | The source label already contains the disclaimer |

## 8. Success metrics

- **SM-1: Exact totals.** The golden-dataset test (NFR-01) matches its expected totals by type and by month exactly. Validates EMI.FR-1, EMI.FR-5 and EMI.FR-6.
- **SM-2: Every number explainable.** 100% of the emission calculations returned by the API carry their factor version, and 100% of source labels contain the demonstration disclaimer. Validates EMI.FR-3 and EMI.FR-4, and goal G2.
- **SM-3: Aggregates are fast.** The summary and monthly responses meet NFR-02. Validates EMI.FR-5 and EMI.FR-6.
- **SM-C1 (counter-metric): History is never trimmed.** The calculation history grows with every save and recalculation. Do not drop or merge history rows to improve SM-3. Counterbalances SM-3.

## 9. Open questions and assumptions

Owner: architect. Needed before CP5. Not a blocker for UX. Details in the [addendum](addendum.md).
2. **Sidebar link vs. page priority.** The Emission Factors sidebar link is part of a Must (FR-PLT-01), but the page is a Should (FR-EMI-08). If the page isn't built, what does the link do? Owner: PM, at CP5 sprint planning.
