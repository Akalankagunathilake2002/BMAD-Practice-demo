- (requirement by sofia) R1 (PLT.FR-1; parent R1): Every signed-in page shows the sidebar and top bar; the sidebar becomes a drawer on narrow screens, works fully by keyboard with visible focus, and hides the Emission Factors entry while that page is not built.
- (requirement by sofia) R2 (PLT.FR-2; parent R13): Switching organization keeps the user on the same page for the new organization and resets the selected period to its default; with no organizations the switcher offers "Create organization".
- (requirement by sofia) R3 (PLT.FR-3; parent R1): Every page has its own address; `/` opens the last-used organization's dashboard or, with none, the organization list; an unknown address or organization shows a not-found page.
- (requirement by sofia) R4 (PLT.FR-4; parent R7, R8): A visitor signs in with a listed demo account and lands on the in-app page they asked for; a failed sign-in does not say which field was wrong, and the password is never shown.
- (requirement by sofia) R5 (PLT.FR-5; parent R9): A signed-in user stays signed in across reloads until 8 hours after sign-in, with no extension; an expired session returns them to sign-in with "Your session has expired", then to the same page.
- (requirement by sofia) R6 (PLT.FR-6; parent R10): The seed creates one demo account per role on example.com addresses, sharing one password from the environment and stored only as a hash; roles restrict nothing.
- (requirement by sofia) R7 (PLT.FR-7, Should; parent R11): Without a valid token, every API call except health, sign-in and the docs gets a 401 saying whether the token was missing, invalid or expired; the docs' Authorize accepts a token.
- (requirement by sofia) R8 (PLT.FR-8; parent R2): Interactive API documentation and the schema are served, and every endpoint has a summary, a description and an example.
- (requirement by sofia) R9 (PLT.FR-9; parent R3): The health check works without a token and returns 200 with each part's status when the API and database are up, 503 when the database is unreachable.
- (requirement by sofia) R10 (PLT.FR-10, Should; parent R6): One reference-data call returns activity types with units, and countries; M0 creates the activity-type list, M1 adds industries and M3 adds scope labels.
- (requirement by sofia) R11 (PLT.FR-11; parent R4): Running the seed command twice changes nothing and keeps users' edits; it creates the demo accounts when demo seeding is on, and M3 and M2 extend the same command with factors and demo data (Decision B).
- (requirement by sofia) R12 (PLT.FR-12; parent R5): On a clean machine with only Docker, copying .env.example to .env and running docker compose up starts a migrated, seeded app reachable only from that machine; a missing .env stops the start with a message naming the copy step.
- (requirement by sofia) R13 (PLT.FR-13; parent Constraints NFR-05): Every API error carries a code, message, field details and request ID, and every response has a request ID; unexpected errors show a generic message, never a stack trace; the UI shows each error with a recovery action and the request ID.
- (requirement by sofia) R14 (PLT.FR-14; parent R38): Shared loading, error-with-Retry and empty-with-one-action components exist, and every data view in M1 to M5 uses them.
- (constraint by sofia) Sign-in is demonstration only: no registration, password reset, role enforcement or server-side sign-out (FR-AUTH-06, architecture §6.5).
- (constraint by sofia) No secret or fallback value in committed files; all configuration comes from the environment, with a placeholder-only .env.example (NFR-06).
- (constraint by sofia) The seed runs on every start, so it must never change data that already exists (PLT.FR-11).
- (constraint by sofia) The API accepts browser requests only from configured origins, and every port listens on the local machine only (NFR-06, architecture §12.2).
